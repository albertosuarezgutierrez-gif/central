  # Concepts

  ### Authentication and authorization
  Authentication is the action of identifying your insurance brokerage as a client of the API. This can be done using
  the [Authentication endpoint](#auth). The `access_token` you will receive identifies your brokerage and must be
  sent in the [Authorization header](#overview--request-headers) during sub-sequent requests in order to be able to
  access other endpoints.

  ### Brokerages and organizations
  The API credentials are associated with an insurance brokerage registered in Avant2. The brokerage is the root
  organization of a hierarchy of organizations configured in Avant2, each one with its own users (see the
  [Avant2 Sales Manager manual](https://app.avant2.es/assets/manual_asm.pdf) for more information).

  API operations usually target the full scope of the brokerage, that means every organization in the hierarchy.
  If you want to execute operations limiting its scope to a specific organization (and its sub-organizations),
  check the [X-User-Email header](#overview--request-headers).

  ### Insurance projects

  An insurance project is an abstraction that represents a series of processes executed with the purpose of fulfilling
  an insurance opportunity, which is a brokerage client (holder) seeking to insure a property or risk.

  This API allows you to create insurance projects, by executing the [quote](#post-/insurances) operation, that can be
  issued later on inside the [Avant2 Sales Manager](https://app.avant2.es) app.

  Learn more about the lifecycle of insurance projects in the
  [Avant2 Sales Manager manual](https://app.avant2.es/assets/manual_asm.pdf).

  ### API versioning

  There is only one version of the API. However, different versions of each operation can co-exist. In that case, they
  will be distinguishable from each other in the sidebar because its summary will include the version number.  

  In order to target a specific version of an operation in the requests, you should send the
  [Content-Type header](#overview--request-headers).

  ## Request Headers
  The main headers you need consider for requests are:
  * **Authorization**: Every request must include this header with the [JWT](https://jwt.io) `access_token`, obtained
  during the [authentication](#auth), following the
  [OAuth 2.0 Bearer token usage specification](https://datatracker.ietf.org/doc/html/rfc6750). It contains information
  to identify your brokerage and <u>grants you access to the API</u>.
  <br/>Example: `Authorization: Bearer [access_token]`<br/><br/>
  * **X-Client-App**: This header will be mandatory eventually. It's requested by insurance 
  vendors to identify the client application from where the access to their services is originated. Please, ask the
  [API support team](mailto:soporteapi@avant2.es) which values are allowed for you brokerage.
  <br/>Example: `X-Client-App: mybrokerage.com`<br/><br/>
  * **Accept**: This header is mandatory for all requests. It lets you specify the desired representation format
  and target version of the operation.
  <br/>Example: `Accept: application/vnd.codeoscopic.v1+json`<br/><br/>
  * **Content-Type**: This header is mandatory for requests that have body, usually POST/PUT/PATCH.
  <br/>Example: `Content-Type: application/json`<br/><br/>
  * **X-User-Email**: By default, operations are executed as the brokerage identified by the `access_token`. This header
  allows you to override this behavior and <u>execute any operation as an individual broker or agent</u> that belongs to
  an organization within your brokerage. Doing so, you will be implicitly limiting the scope of the operation to the
  organization of that user and its sub-organizations depending on the privileges of the specified user.<br/>
  The value of this header should be the email of the Avant2 registered user you want to execute the request
  on behalf of.<br/>
  Some operations, such as the [quote](#post-/insurances) operation, cannot be executed as a brokerage
  and require you to send this header.
  <br/>Example: `X-User-Email: user@brokerage.com`

  ## Request Timeouts
  Some operations may take a while to complete because they require communication with third party services or perform
  long duration tasks. You may need to **configure the timeouts of your HTTP client** accordingly. Also, if you are
  behind a gateway or proxy, you will need to ensure they **allow maintaining the connections open** for as long as
  required.  

  ## Response Headers
  * **Content-Encoding** If the response contains this header with value `gzip`, it means that the content has been
  compressed to reduce the transfer size.<br/><br/>
  * **X-Total-Count**: Returned for pageable operations when requesting the first page (`pageNumber=1`). It contains the 
  total number of items.

  # Product Form Library
  
  There are many products available in the Avant2 marketplace. Most of them define a set of specific options that need
  to be provided in order to complete the rating of the risk covered by the insurance. These options are defined by
  vendors themselves and vary substantially from one vendor to another and, sometimes, even across products of the same
  vendor. Collecting these options in a front-end app, and maintaining these forms whenever the vendor introduces
  changes in the product, would be highly cumbersome and costly for clients of this API. To avoid this burden, we make
  available a JavaScript library that can be easily integrated in front-end apps to render any product form inside an
  <a href="https://html.spec.whatwg.org/#the-iframe-element" target="_blank">iframe</a> and let the users interact with
  it to select the appropriate options for the insurance.

  By leveraging the `Product Form` JavaScript library in your apps, your users will be able to input the specific
  options of each product and you will obtain the output as a JSON object that can be used to
  [quote and insurance project](#post-/insurances) or [re-rate an insurance offer](#post-/insurances/-id-/offers).
  
  This library will be regularly updated to reflect changes in the products, so it's always in sync with the
  vendor's requirements and you don't have to worry about product variability.

  **Note:** You can obtain quotes from the API without using this library. Avant2 defines proper default options for
  each product and also allows you to configure these default options for most products. However, if you plan on using
  this API to complete the rating of these quotes and issue insurance applications, depending on the product you
  will probably be required to specify the final value for certain options in order to achieve these goals.
  Alternatively, you can always complete the rating of these quotes and issue insurance applications through the
  <a href="https://app.avant2.es" target="_blank">Avant2 app</a>. 

  ## Integrate it in your frontend

  ### 1. Configure Content Security Policy (CSP)

  You must configure CSP to allow the library to load the external iframe. To do this, you need to add the following
  rule to your CSP policy.

  **Example:**
  <pre>frame-src &apos;self&apos; *.codeoscopic.io;</pre>

  If you already have a frame-src specified, simply add <code>*.codeoscopic.io</code> to the list.

  ### 2. Load the library
  To load the library in your front-end web app, copy the code shown below and paste it immediately after the head tag
  of the webpage where you want to show the form. You only need one snippet per page.

  **Example:**
  ```html
  <script async src="https://product-form.avant.codeoscopic.io/js.js"></script>
  ```

  ### 3. Create an instance of the product form
  The library provides a class named `AvantProductForm` with a constructor that allows you to create an instance of
  the product form. This constructor will be available once the `script` has finished loading. If you use the
  `async` attribute (recommended) for the loading, you can implement a callback named `avantProductFormInit` in the
  `window` object to be automatically notified when the loading has completed and the constructor is available. 

  After loading the library, you should create an instance of the product form using the constructor of the class
  `AvantProductForm`. The constructor requires two parameters:
  * An **empty** `div` where to insert the `iframe` into. You can specify the div element itself or its `id`.
  * A callback that handles data requests coming from the product form.

  **See:** Section 3.1 for a detailed explanation on the data callback.

  **Example:**
  ```javascript
  window.avantProductFormInit = () => {
    const productForm = new AvantProductForm("DIV_ID", dataCallback);
  }
  ```

  **Signature:**
  ```javascript
  class AvantProductForm {
    /**
    * Creates an instance of the product form.
    *
    * @param elementOrId The div element (or its id) where the iframe will be created.
    * @param dataCallback The callback function that will handle the data requests from the product form.
    * 
    * @returns A new instance of the product form.
    */
    constructor(
        elementOrId: string | HTMLElement,
        dataCallback: <R>(request: Object) => Promise<R>
    ) {};
  }
  ```

  #### The external data callback
  The `iframe` that renders the product form needs to retrieve data from this API in order to work, such as: the initial
  data, the lists of discounts, dynamic options or sub-forms. However, it cannot retrieve this data automatically from
  the API because it doesn't have the `access_token`. Using the API client credentials in non-confidential clients
  (browser) is explicitly <a href="https://datatracker.ietf.org/doc/html/rfc6749#section-4.4" target="_blank">forbidden
  by the OAuth2 protocol</a>. Because of this, the `iframe` delegates any data requests to a callback that must provided
  to the form instance upon creation.

  **Example:**
  ```javascript
  const dataCallback = (request) =>
    fetch("your_endpoint_url", {
        method: "POST",
        body: JSON.stringify(request),
        headers: {
            Authorization: "your_backend_auth_token",
        },
    }).then(async (res) => {
        const response = await res.json();
        if (res.status === 200) {
            return response;
        }
        throw new Error(String(response.message || response.error));
    });
  ```

  The `dataCallback` is a function that must be implemented in your front-end app. It receives a `request` object
  and its responsibility is to forward it to this API and return a
  <a href="https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise" target="_blank">
  promise</a> of the data returned by the API. But, as stated before, the callback function cannot forward the request
  directly to the API (as it's a non-confidential client). Thus, you need to pass the request through a confidential
  client, generally your backend, which has the `access_token` and can make direct requests to this API.
  
  Your confidential API client (backend) must implement an endpoint that should be called by your `dataCallback`. It
  should receive the forwarded request object and make a POST to the`/product-form-requests` resource of this API with
  the request object as the body and the corresponding
  [Authorization, Accept, Content-Type and X-User-Email headers](#overview--request-headers). The result of this POST
  should be returned to the `dataCallback` which, in turn, should forward this result to the `iframe`. This would be
  the diagram of the flow described:  

  <img src="/resources/product-form-callback.png" style="width: 100%" />

  You can try the POST request that your backend should make to our `/product-form-requests` resource in the
  [Execute a product-form request](#post-/product-form-requests) operation.

  #### 4. Render the product form
  You can render the product form with the `render` method. There are two use-cases supported:

  ##### 4.1 Use-case: You want to modify the product options of a quote
  The most common scenario is when you already have a `quote` and you want to modify its product options and re-rate it.
  In this case, you would pass the `quote` object as the single parameter to the `render` function in order to
  populate the form values with the product options already rated in this quote.

  **Example:**
  ```javascript
  productForm.render(quote);
  ```

  **See:** [Retrieve an insurance project](#get-/insurances/-id-) or
  [Retrieve an insurance offer](#get-/insurances/-id-/offers/-offerId-) to obtain the `quote` object.

  ##### 4.2 Use-case: You want to override the default product options 

  The other scenario is when you want to quote a new insurance project but overriding the default product options that
  are configured in your organization. In this case, you would pass the `insurance` object you want to quote and the
  `product` object whose options you want to customize. The product form would then be populated with the default
  product options configured for this product and show only the options suitable for the insurance specified.

  **Example:**
  ```javascript
  productForm.render(insurance, product);
  ```

  The `product` object must contain a single `config` of the available product configurations returned by the
  [List insurance products](#get-/insurance-lines/-id-/products) operation.

  **Example:**
  ```json
  {
    "config": {
      "id": 12345
    }
  }
  ```

  ##### 4.3 (Optional) Pass the default options when render

  Additionally, you can render the form by passing the default options,
  use the third parameter of the `render` method to set the initial options.

  This is useful when you save these options using the `getProductOptions` method, and you
  want to render the form with those options.

  **Example with quote:**
  ```javascript
  productForm.render(quote, undefined, initialOptions);
  ```

  **Example with insurance and product options:**
  ```javascript
  productForm.render(insurance, product, initialOptions);
  ```

  **See:** [Quote an insurance project](#post-/insurances) to examine the schema of the `insurance` object.
  

  ### 5. Get the product options
  Once the iframe has rendered the form, you can obtain the product options with the method `getProductOptions`. This
  method gathers the form values and returns a
  <a href="https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise" target="_blank">
  promise</a> of a JSON object that represents the array of chosen product options.

  The returned JSON object can be used in the [quote and insurance project](#post-/insurances) and
  [re-rate an insurance offer](#post-/insurances/-id-/offers) operations to specify what options to use for rating each
  product. 

  **Example:**
  ```javascript
  const values = await productForm.getProductOptions();
  ```

  **Signature:**
  ```javascript
  /**
  * @returns A promise of the product options chosen in the form or an Error if the form validation fails.
  */
  getProductOptions(): Promise<readonly Object[] | ValidationError>;
  ```
